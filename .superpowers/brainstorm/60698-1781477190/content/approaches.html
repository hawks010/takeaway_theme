Three ways to build Reservations + CRM

Each has a different data model and complexity trade-off — pick the one that fits

A

Reservations-first, minimal CRM

Ship fast, decide CRM later
Data model
ttos_reservation CPT Guest name/email stored on booking only No separate customer record
✓ Fastest to build
✓ No cross-system complexity
✓ Works without WooCommerce accounts
✗ No customer history view
✗ Staff can't see "this person booked 4× before"
✗ CRM has to be added later as a separate effort
B

WooCommerce-native

Reservations are WC orders
Data model
WC Order (booking type) WC Customer account My Account integration built-in
✓ Deposits & payments built-in via WC
✓ Customer sees booking in My Account automatically
✓ One data system for orders + bookings
✗ WC order flow is awkward for time-slot bookings
✗ Hard to query "show me all bookings for tonight"
✗ WC admin UI not designed for reservation management
C

Custom CPT + WC link Recommended

Clean separation, smart connections
Data model
ttos_reservation CPT ttos_customer CPT (CRM record) WC account link (optional)
✓ Reservations are first-class — easy to query & manage
✓ CRM records exist for all guests (logged-in or not)
✓ Logged-in customers see bookings in My Account
✓ Staff can add notes, allergies, VIP flags per customer
✓ Guest bookings can be merged with WC account by email
✗ More upfront build than A
✗ Two post types to maintain vs. piggy-backing WC
Why I recommend C: The reservation admin screen needs to show tonight's bookings sorted by time, flagged by status, with customer notes visible at a glance. WooCommerce orders are not designed for that view — you'd be fighting the data model constantly. Custom CPTs give you clean queries, a purpose-built admin, and a real CRM layer that works for both guests and logged-in customers.
