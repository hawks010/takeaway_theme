Reservation + CRM — Full Architecture

Two custom post types, one admin, one public form. Everything connects cleanly.

ttos_reservation (post type)

  • date / timeWhen the booking is for
  • coversParty size
  • statuspending → confirmed → seated → done
  • customer_id→ links to ttos_customer record
  • wc_user_id→ links to WC account (if logged in)
  • wc_order_id→ deposit order (if deposit taken)
  • tableTable name / number (optional)
  • sourceonline | staff
  • notesCustomer's special requests
  • deposit_requiredbool + amount

ttos_customer (post type — CRM record)

  • name / email / phoneContact details
  • wc_user_id→ linked WC account (matched by email)
  • is_vipVIP flag — shown in admin booking list
  • allergensDietary/allergy notes
  • staff_notesPrivate notes (regulars, preferences)
  • booking_countTotal bookings (denormalised)
  • last_bookingDate of most recent reservation
Created automatically on first booking. Two bookings with the same email → same customer record.

Reservation status lifecycle

Pending → Confirmed → Seated → Completed
Pending → Cancelled    Confirmed → Cancelled    Confirmed → No-show
Auto-confirm rule: ≤ N covers (configurable in CRM, default 6) → straight to Confirmed on submission.
Deposit flow: if deposit required → stays Pending until WooCommerce payment clears → then Confirmed.
Seated: staff marks arrival — this is the point where a kitchen order can optionally be tagged to this reservation.

Public booking form

  • Date + time picker
  • Party size
  • Name / email / phone
  • Special requests (optional)
  • Capacity check (if enabled)
  • Deposit step if required
  • Shortcode: [ttos_booking_form]

Staff admin panel

  • Today's bookings — sorted by time
  • Filter by date / status
  • Quick actions: confirm / cancel / seat / no-show
  • Manual entry form
  • Customer profile panel (side-by-side)
  • Email log (what was sent)

Emails sent automatically

  • → Customer: booking received
  • → Customer: booking confirmed
  • → Customer: reminder (24h before)
  • → Customer: cancellation
  • → Staff: new booking alert
  • → Staff: cancellation alert

WooCommerce connections

Deposit payments
Deposit required → WC order created → payment clears → reservation auto-confirms. Order tagged with reservation ID.
My Account tab
Logged-in customers see "My Bookings" in My Account. Guest bookings auto-link to a WC account if same email exists.
Kitchen ticket tag
When a reservation is Seated, staff can create a WC order tagged with "Table X — Smith x6". Shows on kitchen screen.
