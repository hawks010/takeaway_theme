# Takeaway OS v1.3.0 / Takeaway Theme v0.3.0 — Audit & Implementation Plan

Date: 2026-06-10
Explored: local workspace (`~/Documents/Takeaway theme`) + live staging (`https://takeaway.thatdeveloper.co.uk`, docroot `~/domains/thatdeveloper.co.uk/public_html/takeaway`).
No changes were made to staging during this audit (read-only WP-CLI + browser inspection only).

## Part 1 — What exploration found

### 1.1 Codebase shape

**Theme (`takeaway-theme` 0.2.6, 17 files, ~250 lines PHP + one minified CSS file):**
- Templates: `front-page.php`, `page.php`, `index.php`, `archive-product.php`, `header.php`, `footer.php`. No `404.php`, no `woocommerce/` overrides, no template parts, no searchform, no comments template.
- `front-page.php` hardcodes English marketing copy ("Hot food. Zero fuss. Direct.", "Pick your obsession", "Built for busy kitchens") and a **hardcoded Unsplash fallback hero URL**.
- `assets/css/theme.css` is one minified file with 4 colour "skins" (`tt-skin-charcoal/burger/pizza/clean`) keyed off a body class. Under 900px the primary nav is `display:none` — **there is no mobile menu at all**.
- `inc/plugin-checklist.php` (458 lines) is the bundled-plugin installer/updater (works; verified 1.2.4→1.2.5 on staging previously).
- Theme reads plugin settings via `ttheme_business()`/`ttheme_brand()` helpers with graceful fallbacks, and uses `shortcode_exists()` guards. Good decoupling pattern — keep.

**Plugin (`takeaway-os` 1.2.5, 16 classes, ~7,200 lines):**
- `TTOS_Settings` — single `ttos_settings` option, sections: `business`, `branding`, `trading`, `service_links`, `modules` (17 flags), `data_retention`. Branding today = logo_id, hero_image_id, 4 hex colours, style_skin. Brand CSS = 4 inline `:root` vars printed in `wp_head`.
- `TTOS_Page_Manager` — generated pages with HTML marker comments (`<!-- takeaway-os:key -->`), `_ttos_generated_page` meta, safe modes (`fresh_if_unsafe` / `append` / `replace`), `ttos_page_*` option registry, Woo page assignment sync, nav-menu seeding. **Solid foundation — extend, don't replace.**
- `TTOS_Shortcodes` — `[takeaway_menu]` (full grid + configurator modal + sticky basket), `[takeaway_delivery_checker]` (fake: inline `onsubmit` always answers "Looks good"), `[takeaway_order_tracker]`, `[takeaway_allergens]` (static card), `[takeaway_customer_portal]`, `[takeaway_kitchen_screen]`.
- `TTOS_Features` (1,114 lines) — meal deals, loyalty, advanced zones, integrations (SMS/printer/EPOS with retry queue), and the current "content manager": **six fields** (hero eyebrow/title/text, offer title/text, CTA label/URL) rendered by `[takeaway_home_blocks]`, gated behind the `content_manager` module flag.
- `TTOS_Admin` (1,738 lines) — admin shell + Launchpad wizard, Menu Builder, Orders cockpit (AJAX polling board), Kitchen Screen, Customers (CRM with segments/campaigns), Reports, Business Settings, Payments, Delivery, Add-ons (module locks).
- `TTOS_Setup_Health` — 36 checks incl. payment gateway/Stripe mode/SMTP/sender/roles. Tuple-based check framework, easy to extend.
- `TTOS_Operations` — checkout fulfilment fields/validation, handover roles, logs. `TTOS_Production` — go-live checklist, starter menu, pause switch, page repair. `TTOS_Hardening` — capability sync + system checks. `TTOS_WooCommerce` — option groups (configurator), custom order statuses, allergen/dietary taxonomies, cart item meta. `TTOS_Analytics` — reports + CSV exports.
- Security posture on saves is good (nonces + capability checks throughout `handle_posts`). Cart/checkout flow verified working on staging (order #460 BACS).

**Workspace state:** git repo initialised but **zero commits** — no version history safety net. Release zips and `TAKEAWAY_OS_PROGRESS.md` live alongside source.

### 1.2 Live staging defects (browser-verified, with root causes)

1. **Theme header and footer never render — site-wide.** Root cause: leftover Elementor Pro Theme Builder data from the old "blueprint" site. `elementor_pro_theme_builder_conditions` = `{"elementor_head":{"61":…,"37":…},"footer":{"40":["include/general"]}}`. Template 40 ("Website Footer", publish) has a site-wide condition, so Elementor Pro replaces `header.php`/`footer.php` with its own theme-builder templates: no theme header is printed at all (no header template exists), and the **old "© 2026 – Blueprint. All Rights Reserved / Built & Maintained by Inkfire" Elementor footer renders at the bottom of every page**. Entries 61/37 point at deleted posts (ghost conditions). This single issue removes nav, branding, basket access and the theme footer from every page. Note: earlier smoke tests recorded "header/footer render: Pass", so this either regressed when Elementor Pro was (re)activated or conditions were re-saved later.
2. **Broken hero image**: hardcoded Unsplash URL returns no image → empty white circle with stray alt text on desktop and mobile.
3. **Invisible homepage content**: `[takeaway_home_blocks]` renders white text on a white card. `theme.css` v0.2.3 overrides `.ttos-home-blocks` background to `#fff` while `frontend.css` keeps heading/text white (designed for the dark card). Offer text is white-on-beige. Computed styles verified: `background rgb(255,255,255)`, `h1 color rgb(255,255,255)`.
4. **Homepage shows the full menu/order grid** (front-page.php embeds `[takeaway_menu]`) — exactly what v1.3.0 must remove in favour of a sales-funnel homepage.
5. **Admin helper text leaks publicly**: empty categories ("Chicken", "Desserts", "Uncategorized") render on the public homepage/menu with "No menu items are live yet. Add products in Takeaway OS → Menu Builder…". "Uncategorized" is shown as a public category tab.
6. **Menu page double heading**: `archive-product.php` prints a giant page-head "Menu", then `[takeaway_menu]` prints its own "ORDER DIRECT / Menu" head + duplicate delivery checker.
7. **Raw WooCommerce UI** on basket/checkout/account: default blue-bordered notices, grey buttons, default tables/forms.
8. **Sticky basket bar wraps badly** — `WC()->cart->get_cart_subtotal()` HTML breaks mid-amount ("£" / "0.00" on separate lines).
9. **No mobile navigation** (CSS hides nav <900px, no drawer) and no basket/account affordance in header even when header renders.
10. **Duplicate pages on staging**: front page = generated "Takeaway Home" (422) while old Elementor "Home" (30, `elementor_header_footer` template) is still published; Woo account page = "Takeaway My Account" (424) while old "My Account" (395) is still published. Old "Contact" (94) and "Privacy Policy" (3) are unstyled strays. (Setup Health does not currently flag duplicates — brief asks for this check.)
11. **Placeholder identity everywhere**: `blogname` = "blueprint", site icon = 🐴 emoji (attachment 99) — appears in every tab title; sender shows `"blueprint" <webmaster@inkfire.co.uk>`.
12. **No 404 template** (index.php "Nothing found" card), no contact/policy templates, tracker/allergens are bare cards.
13. **Delivery checker is fake** — inline JS always replies "Looks good. We will confirm at checkout." regardless of postcode.
14. **Staging plugin pollution**: Elementor + Elementor Pro + Essential Addons + Envato Elements + Rank Math (+Pro) + AAM + Hostinger tooling all active. Not part of the product stack; Elementor Pro is actively breaking the theme (defect 1).

## Part 2 — Architecture decisions for v1.3.0 / v0.3.0

**D1. Pages stay as thin shortcode containers; layout lives in the theme; content lives in options.**
Generated pages keep marker + shortcode only (update-safe; client content never in theme files). The theme renders structure around them. Homepage becomes a *section renderer* driven by the Site Content CRM — not a page full of HTML.

**D2. New option: `ttos_site_content` (versioned), separate from `ttos_settings`.**
Sections keyed by tab (homepage, menu_page, business hours mirrors, contact_map, reviews, offers, social, footer, policies, banner, popup). All images stored as attachment IDs. `ttos_settings.branding` is extended in place (migration pads new keys; never overwrites existing values). Export/import covers `branding` + `ttos_site_content` as one JSON bundle with version stamp.

**D3. Design tokens replace "skins".**
`TTOS_Settings::print_brand_css()` grows to emit the full token set: `--tt-primary, --tt-accent, --tt-bg, --tt-surface, --tt-surface-soft, --tt-text, --tt-muted, --tt-border, --tt-success, --tt-warning, --tt-error, --tt-radius-sm/md/lg, --tt-shadow`. Legacy vars (`--tt-secondary, --tt-dark, --tt-cream`) remain as aliases so 0.2.x CSS keeps working. Light/dark/system via `data-tt-mode` on `<html>` + `prefers-color-scheme`; dark mode = token swap, not a second stylesheet. Existing skins become *presets* that prefill token values in Branding.

**D4. Theme gets a real template architecture (classic theme, no builder):**
```
takeaway-theme/
  front-page.php            → loops enabled home sections
  template-parts/
    header/ (site-header, mobile-drawer, banner)
    home/   (hero, trust-strip, featured, why-direct, offers,
             about, booking, hours, contact-map, reviews, signup, cta)
    footer/ (site-footer)
    menu/   (page-head, category-nav)
  404.php, page-policy.php (template for policy pages)
  woocommerce/ (cart/cart.php + cart-empty, checkout form wrappers,
                myaccount/ navigation + dashboard, form-login.php,
                checkout/thankyou.php)
  assets/css/  tokens.css, base.css, header.css, home.css, menu.css,
               woo.css, utility.css  (unminified source, small files)
  assets/js/   theme.js (drawer, sticky), banner.js, popup.js
```
Every section: render only if content exists; neutral grey/white placeholder block in admin-preview contexts; hidden publicly when empty. Zero hardcoded marketing copy — all strings from Site Content with neutral fallbacks ("Order online", business name, etc.). Developer extension points: `ttos_home_sections` filter (order/enable), `tt_token_defaults` filter, child-theme template-part overrides, documented hooks.

**D5. WooCommerce restyle = CSS-first, minimal template overrides.**
Style notices, forms, buttons, tables via scoped `.tt-` wrappers + tokens. Override only templates where structure must change (cart layout, account nav, thankyou). Never touch checkout field logic (Operations already owns fulfilment fields). HPOS stays declared.

**D6. Banner + popup are plugin features rendered via hooks** (`wp_body_open` for banner, `wp_footer` for popup), config in Site Content, schedule-aware (UTC stored, site TZ compared), dismissal in `localStorage` keyed by content hash, focus-trap + ESC + labelled close; popups suppressed on checkout/cart unless explicitly enabled. Server prints config; tiny vanilla JS handles behaviour. No third-party code.

**D7. Page Manager grows policy + utility specs** (contact, privacy, cookies, terms, refunds, delivery policy, accessibility, hygiene) with starter content carrying a visible admin-only reminder ("Starter content only. Review before production." — rendered via a marker shortcode that outputs nothing publicly except the policy body, and a notice in editor/admin list). Footer legal menu seeded the same way nav menus already are. Existing repair modes (`append`/`replace`-with-confirmation) reused as-is.

**D8. Elementor defence (new Setup Health checks + repair).**
- Check: active theme-builder conditions hijacking header/footer (`elementor_pro_theme_builder_conditions` non-empty while takeaway-theme is active) → **fail, critical**, with repair action "Disable conflicting Elementor theme-builder templates" (sets those templates to draft after explicit confirmation; never deletes).
- Check: duplicate Home/My Account/Menu candidates (same slug family or same Woo assignment ±_published twins) → warning with list.
- Checks: branding minimum (logo, primary colour), site content minimum (hero heading or business name, opening hours), banner/popup schedule validity, footer legal links present, site identity not placeholder (blogname "blueprint"/emoji icon → warning).
Elementor remains strictly optional — the product must never require it; these checks only *protect* the native theme from leftovers.

**D9. CRMs stay separate, connected at render time.** Customer CRM (`TTOS_Admin` customers/campaigns) untouched. Site Content CRM is a new admin class (`class-site-content.php`). Front-end touchpoints (reviews section, loyalty blocks, VIP badges on tickets) read Customer CRM only if module enabled; degrade to hidden sections otherwise.

**D10. KDS-lite preserved.** No changes to order statuses, cockpit AJAX endpoints, or kitchen screens in this release beyond CSS-token adoption in admin shell. Ticket system integration points (priority/VIP badge) read-only.

## Part 4 — Risks & guardrails

- **Elementor Pro hijack** is environmental, not code — staging fix is config (draft template + clear conditions) and the durable fix is the Setup Health check. Other client sites with Elementor leftovers would hit the same trap; the check is therefore product-critical.
- Checkout regressions are the biggest blast radius in Phase 5 — mitigate by overriding the minimum set of Woo templates, re-running the BACS order after each override, and keeping `TTOS_Operations` checkout logic untouched.
- Existing client content: all new page generation goes through existing safe modes; migrations only add keys; no automatic content replacement anywhere.
- Staging carries non-product plugins; after cleanup, re-run Setup Health expecting the same 36-pass baseline before starting Phase 1.
- Paid production remains blocked on live Stripe + SMTP verification regardless of this release.
